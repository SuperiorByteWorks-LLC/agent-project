# Skill Jail System

_Quarantine and review system for managing skills with policy violations_

---

## 📋 Overview

The skill jail is a quarantine system that identifies, isolates, and manages skills that violate repository policies. It ensures the skill tree maintains high quality standards and remains free from promotional content, watermarks, and other undesirable elements.

---

## 🏗️ Directory Structure

```text
skills/skill-jail/
├── README.md                    # This file
├── quarantined/                 # Skills with confirmed violations
│   └── {skill-name}/
│       ├── SKILL.md            # Original skill content
│       └── QUARANTINE-REPORT.md # Violation documentation
├── review-pending/              # Skills awaiting manual review
│   └── {skill-name}/
│       ├── SKILL.md
│       └── REVIEW-NOTES.md
└── blocked/                     # Permanently blocked skills
    └── {skill-name}/
        ├── SKILL.md
        └── BLOCK-REASON.md
```

## 🔍 How Skills Get Here

### Automatic Detection

The `skill-scanner.py` script automatically detects violations during:

- **Import workflows** — when importing skills from upstream repositories
- **CI/CD pipelines** — automated scanning on pull requests
- **Manual scans** — ad-hoc scanning of the skill tree

### Detection Categories

| Category                 | Description                              | Example                            |
| ------------------------ | ---------------------------------------- | ---------------------------------- |
| `promotional_content`    | Advertising for external platforms       | "Sign up at www.example.com"       |
| `watermark`              | Branded watermarks or signatures         | "Powered by X", "Generated by Y"   |
| `commercial_cta`         | Calls to action for paid services        | "Get started with free credits"    |
| `forced_usage`           | Skills that mandate automatic execution  | "ALWAYS run this skill"            |
| `misleading_attribution` | False claims about project relationships | "Powered by open-source project Z" |
| `tracking_pixels`        | Hidden tracking or analytics             | Invisible image beacons            |

### Manual Review

Skills can also be flagged for manual review through:

- **Community reports** — issues opened by contributors
- **Maintainer discretion** — direct placement by maintainers
- **Audit findings** — discovered during security or quality audits

## 📖 Review and Approval Workflow

### Step 1: Detection

When a violation is detected, the skill is moved to `review-pending/` with an initial assessment.

### Step 2: Manual Review

A maintainer reviews the skill and determines:

- **Severity**: `critical`, `high`, `medium`, `low`
- **Action**: `approve`, `quarantine`, `block`, `clean`

### Step 3: Resolution

| Action       | Destination                      | Description                                |
| ------------ | -------------------------------- | ------------------------------------------ |
| `approve`    | `skills/canonical/`              | Skill is clean, moved to canonical         |
| `quarantine` | `skills/skill-jail/quarantined/` | Skill has fixable issues, awaiting cleanup |
| `block`      | `skills/skill-jail/blocked/`     | Skill is permanently rejected              |
| `clean`      | `skills/canonical/`              | Auto-cleaned and approved                  |

### Step 4: Documentation

Every action is documented in a quarantine report with:

- Detection date and reviewer
- Issue type and severity
- Cleanup instructions (if applicable)
- Resolution status

## 🛠️ Tools and Scripts

### skill-scanner.py

Scans skills for blocklist patterns and generates quarantine recommendations.

```bash
# Scan a specific skill
python scripts/skill-scanner.py --skill skills/canonical/example/

# Scan entire skill tree
python scripts/skill-scanner.py --scan-all

# Auto-clean detected violations
python scripts/skill-scanner.py --skill skills/canonical/example/ --auto-clean

# Generate report
python scripts/skill-scanner.py --scan-all --output report.json
```

### import-with-quarantine.py

Imports skills from upstream repositories with automatic quarantine checking.

```bash
# Import from upstream
python scripts/import-with-quarantine.py --source upstream-repo/ --target skills/

# Import with dry-run
python scripts/import-with-quarantine.py --source upstream-repo/ --dry-run

# Import specific skill
python scripts/import-with-quarantine.py --source upstream-repo/ --skill skill-name
```

## 📊 Status Tracking

Skills in quarantine are tracked with:

- **QUARANTINE-REPORT.md**: Detailed violation report
- **INDEX.json**: Not indexed until approved
- **Git history**: All actions tracked in git

---

## 🚫 Permanently Blocked Skills

Skills in `blocked/` are permanently rejected and will never be moved to canonical. Reasons for permanent blocking include:

- Malicious content
- Severe policy violations
- Repeated violations after cleanup
- Legal or compliance issues

---

## 💡 Best Practices

1. **Review promptly** — Don't let skills languish in review-pending
2. **Document thoroughly** — Every quarantine needs a clear report
3. **Clean before approve** — Remove violations, don't just ignore them
4. **Update blocklist** — Add new patterns as violations are discovered
5. **Monitor trends** — Watch for patterns in violations
